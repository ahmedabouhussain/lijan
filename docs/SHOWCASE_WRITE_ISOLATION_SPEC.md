# مواصفة الكتابة التجريبية المعزولة + عقد تكليف المراجعة — LIJAN™

**حالة التنفيذ: `SPECIFIED — NOT EXECUTED`**
لم تُكتب أي بيانات مشتركة. جلسات العرض الحالية ما زالت `write_scope: none`. هذا المستند يثبّت القرار والقيود قبل التنفيذ، بحسب ما طُلب.

---

## 1. حكم القيد على المنصة (مطلوب قبل الكتابة)

**الطبقة المنفصلة ممكنة تقنيًا — لا مانع من المنصة.** لكن التنفيذ يستلزم ثلاثة تغييرات متلازمة، ولا يجوز تنفيذ جزء منها:

| المتطلب | الحالة | الأثر إن نُفّذ منفردًا |
|---|---|---|
| قراءة خط الأساس | ممكن (`ListCommitteeRegister` / `GetCommitteeRecord` / `GetCommitteeMiniPortal`) | — |
| طبقة كتابة لكل جلسة | ممكنة كسجل تجاوز (overlay) مستقل | كتابة لا تظهر عند تحديث الصفحة إن لم يُدمج التجاوز في القراءة |
| دمج التجاوز وقت القراءة | **إلزامي في المسارات الثلاثة** | تسرّب بيانات الجلسة إلى مستخدم عرض آخر، أو اختفاء الأثر بعد التحديث |
| انتهاء الصلاحية (`expires_at`) | ممكن كحقل + فلترة عند القراءة | تراكم سجلات بلا انتهاء |
| تنظيف وفق سياسة احتفاظ | لا يوجد TTL أصلي في المنصة ⇒ يلزم مهمة مجدولة | بقاء بيانات الجلسات إلى الأبد |
| تدقيق موسوم `showcase` | ممكن كحقل/سجل مخصّص | اختلاط أثر العرض بالأثر المؤسسي |

**القيد الحقيقي ليس القدرة، بل الترتيب**: لا يُفتح `write_scope` قبل أن تعمل القراءة المدموجة والتنظيف والوسم — وإلا صارت الكتابة غير معزولة فعليًا.

## 2. نموذج البيانات (لا يُنشأ إلا في التنفيذ)

**`ShowcaseRun`** — الرحلة الواحدة:
`showcase_run_id` · `showcase_dataset_id` · `base_fixture_version` · `created_by_showcase_session` · `persona_key` · `expires_at` · `reset_status` (`open` | `reset` | `expired` | `cleaning`) · `retention_days` · `shared_with_runs[]` (لاستثناء الرحلات المشتركة عمدًا).

**`ShowcaseOverlayWrite`** — الكتابة الواحدة:
`showcase_run_id` · `entity_type` · `source_record_id` (فارغ للإنشاء) · `payload_json` · `operation` (`create`|`patch`|`delete`) · `transition_id` · `idempotency_key` · `created_by_showcase_session` · `audit_flag: "showcase"` · `created_at` · `expires_at`.

قواعد ملزمة:
1. لا يُكتب أي حقل فوق سجل خط الأساس — التجاوز سجل منفصل دائمًا.
2. كل كتابة تحمل `showcase_run_id` + `audit_flag: "showcase"`؛ لا كتابة بلا Run.
3. القراءة = خط الأساس + تجاوزات نفس الـ Run فقط (و`shared_with_runs` عند المشاركة المقصودة).
4. إعادة الضبط = تحويل `reset_status` إلى `reset` + إسقاط تجاوزات الرحلة؛ لا تمس السجلات الحقيقية ولا خط الأساس المعتمد.
5. الاحتفاظ: `expires_at = created_at + retention_days` (مقترح: 7 أيام)، ومهمة مجدولة يومية تُسقط المنتهي وتُقفل الرحلات.
6. الكتابة تُنفَّذ في دالة خلفية بصلاحية الخدمة + جلسة عرض صالحة (`showcase_token`)، ولا تُقبل `showcase_run_id` إلا من جلسة صالحة.
7. أي كتابة تُنتج حدث تدقيق موسومًا `showcase`، وإشعارًا تجريبيًا لا يخرج خارج المنصة.

**الحديث مع التزامن**: كل انتقال يحمل `transition_id` + `idempotency_key`؛ النقر المزدوج أو الطلبان المتزامنان يعيدان نفس النتيجة بلا كتابة ثانية.

## 3. عقد تكليف المراجعة (يفصل خمسة مفاهيم)

| المفهوم | الحقل | لماذا |
|---|---|---|
| الأهلية للمراجعة | `eligible_role`, `eligible_capability` | شرط دخول فقط، لا يُنشئ تكليفًا |
| الشخص المكلَّف | `assignee_person_id` | لقطة هوية |
| المقعد/العضوية | **`assignee_membership_id`** (المرجع التشغيلي الأساسي) | السلطة تأتي من العضوية لا من الاسم |
| المقعد الرسمي | `assignee_seat_id` | عند وجود مقعد معرّف |
| حق الاعتماد | `required_capability` (`review.comment` \| `review.request_changes` \| `review.approve`) | الاعتماد ليس صفة المسمى |
| التفويض/البديل | `assignment_snapshot` | الدور والجهة وتاريخ السريان وقت التكليف |
| حالة المهمة | `status` | حالة تشغيلية مستقلة |

**محظور:** تكليف يحمل دورًا بلا مستلم محدد. `reviewer_user_id` يبقى للقراءة فقط (توافق) ولا يُنشئ به تكليف جديد. خطة الترحيل غير مدمرة: قراءة مزدوجة (القديم ← الجديد) ثم إسقاط القديم قراءةً بعد دورة تحقق واحدة، دون حذف أي سجل.

**سجل حالات المهمة (انتقالات على الخادم):**
`pending → opened → commented → changes_requested → resubmitted → approved | rejected | cancelled`

| الانتقال | الفاعل المؤهل | الحالة السابقة | المدخلات الإلزامية | أثر البيانات | التدقيق |
|---|---|---|---|---|---|
| pending→opened | المكلَّف نفسه | pending | — | `opened_at` | `review.opened` |
| opened→commented | المكلَّف | opened | نص التعليق | `SharedComment` | `review.commented` |
| commented→changes_requested | المكلَّف (بأهلية) | opened/commented | سبب + `document_version_id` | طلب تعديل | `review.changes_requested` |
| changes_requested→resubmitted | المُقدِّم | changes_requested | إصدار جديد (`DocumentVersion` ≥ السابق+1) | إصدار جديد **لا يستبدل السابق** | `review.resubmitted` |
| →approved | صاحب `review.approve` | resubmitted | مطابقة `document_version_id` للحالي | اعتماد الإصدار | `review.approved` |
| →rejected | صاحب `review.approve` | resubmitted | سبب | رفض موثّق | `review.rejected` |
| →cancelled | المُقدِّم أو الرئيس | أي حالة مفتوحة | سبب | إغلاق | `review.cancelled` |

قيود إلزامية: لا اعتماد لإصدار قديم بعد رفع أحدث؛ ولا اعتماد مستند تغيّر محتواه بعد بدء المراجعة دون إعادة تأكيد (`document_fingerprint`).

## 4. رحلة الدكتور حمد (لجنة الابتكار وتطوير الخدمات فقط)

دوره المعتمد فيها **أمين سر**. الرحلة المطلوبة ومصيرها المتوقع:

1. وثيقة عرض حقيقية + `DocumentVersion` بملف قابل للمعاينة.
2. تكليف صريح على **عضوية الدكتور حمد في هذه اللجنة** (`assignee_membership_id`).
3. تعليق محفوظ (`SharedComment`) ← `commented`.
4. طلب تعديل مع سبب ← `changes_requested`.
5. إصدار جديد (نسخة N+1) لا يستبدل السابق ← `resubmitted`.
6. التاريخ الكامل للإصدارات ظاهر.
7. حدث تدقيق لكل انتقال + منع التكرار والتزامن.
8. ظهور النتيجة بعد تحديث الصفحة (من طبقة الكتابة نفسها).

**النهاية الإلزامية:** بما أن الأمين لا يحمل `review.approve` (منحة الابتكار `secretary_administration`)، فإن الرحلة تنتهي:
**«إكمال المراجعة ورفعها إلى صاحب سلطة الاعتماد»** — ولا يُمنح الاعتماد لإكمال العرض.

## 6. تقوية جلسة الاستكشاف (الخطر المتبقي معلن)

يبقى التصنيف: **`ACCEPTED FOR CONTROLLED SHOWCASE WITH RESIDUAL XSS TOKEN RISK`**.

| البند | الحالة |
|---|---|
| انتهاء عند الخمول + انتهاء مطلق | مطلوب (لا يوجد انتهاء بالخمول الآن — OPEN) |
| تنظيف الرمز عند الخروج (Exit/Reset) | مطلوب |
| إسقاط بيانات الواجهة المحمية بعد الإلغاء | مطلوب |
| منع تخزين الرمز في عامل الخدمة/الذاكرة دون اتصال | مطلوب (يتقاطع مع `public/lijan-sw.js`) |
| تدوير الرمز عند الانتقال إلى نطاق كتابة | مطلوب قبل فتح `write_scope` |
| فحص CSP من استجابة المعاينة فعليًا | لم يُنفّذ — لا يُدّعى وجودها من الكود |
| جرد السكربتات الخارجية القادرة على قراءة `sessionStorage` | لم يُنفّذ (OPEN) |

لا يُدّعى معالجة XSS ما دام الرمز متاحًا لـ JavaScript.
